<ParamField path="POST https://api.wizebot.com.br/api/v1/whatsapp/messages" />

Envia uma mensagem de texto ou de mídia. A resposta é `201 Created` assim que a mensagem é aceita para envio.

## Antes de integrar

Três regras definem o que este endpoint consegue fazer. Vale ler as três antes de escrever o código.

<Warning>
  **Só é possível responder a conversas existentes.** Se o número de destino nunca conversou com o seu número de WhatsApp, o envio é recusado. A recusa chega como `500` com código `SEND_FAILED`.
</Warning>

<Warning>
  **Não há envio de modelo de mensagem nesta API.** O campo `type` aceita apenas `text`, `image`, `document`, `audio` e `video`. Como o modelo é o único jeito de falar com quem está fora da janela de atendimento, não há como iniciar conversa por aqui.
</Warning>

<Warning>
  **A janela de atendimento de 24 horas não é verificada neste caminho.** Uma mensagem enviada fora da janela é aceita com `201` e depois recusada pelo WhatsApp. O envio parece ter dado certo e a mensagem não chega. Confirme a entrega pela [consulta de status](/tutoriais/api/status-mensagem-whatsapp) — é o único jeito de saber.
</Warning>

## Parâmetros

<ParamField body="phone_number_id" type="string" required>
  Identificador do seu número de WhatsApp na Meta.
</ParamField>

<ParamField body="phone_number" type="string" required>
  Número do destinatário, com código do país e apenas dígitos. Veja [Formato do telefone](#formato-do-telefone).
</ParamField>

<ParamField body="type" type="string" default="text">
  Um de `text`, `image`, `document`, `audio`, `video`.
</ParamField>

<ParamField body="message" type="string">
  Texto da mensagem. Obrigatório quando `type` é `text`. Máximo de 4096 caracteres.
</ParamField>

<ParamField body="media_url" type="string">
  URL pública da mídia. Obrigatório para os tipos de mídia. Veja [Regras da mídia](#regras-da-midia).
</ParamField>

<ParamField body="caption" type="string">
  Legenda, para `image`, `document` e `video`. Ignorada em `audio`.
</ParamField>

<ParamField body="filename" type="string" default="document">
  Nome do arquivo, para `document`.
</ParamField>

## Formato do telefone

Envie **apenas dígitos, com código do país**: `5511999999999`.

<Note>
  A API não normaliza o telefone para você em todos os caminhos. Os endpoints de contato comparam o número **literalmente** com o que está gravado, então `+55 11 99999-8888` e `5511999998888` são valores diferentes para eles. Adote dígitos com código do país em toda a integração e você não esbarra nisso.
</Note>

## Regras da mídia

A `media_url` precisa ser um endereço **público** em `http` ou `https`. URLs que apontam para rede interna, endereço de loopback ou serviço de metadados de nuvem são recusadas com `400 INVALID_MEDIA_URL`, antes de qualquer download.

| Tipo | Como a mídia é entregue |
|---|---|
| `image`, `document`, `video` | A URL é repassada ao WhatsApp, que faz o download |
| `audio` | O arquivo é baixado pelo nosso servidor e enviado ao WhatsApp |

<Note>
  A URL precisa continuar acessível por alguns minutos depois do envio. Links assinados com validade muito curta podem expirar antes do download.
</Note>

## Exemplos

<CodeGroup>
```bash Texto
curl -X POST 'https://api.wizebot.com.br/api/v1/whatsapp/messages' \
  -H 'Authorization: Bearer API-KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "phone_number_id": "119153661148976",
    "phone_number": "5511999999999",
    "message": "Seu pedido saiu para entrega."
  }'
```

```bash Imagem
curl -X POST 'https://api.wizebot.com.br/api/v1/whatsapp/messages' \
  -H 'Authorization: Bearer API-KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "phone_number_id": "119153661148976",
    "phone_number": "5511999999999",
    "type": "image",
    "media_url": "https://exemplo.com/comprovante.jpg",
    "caption": "Comprovante do pedido"
  }'
```

```bash Documento
curl -X POST 'https://api.wizebot.com.br/api/v1/whatsapp/messages' \
  -H 'Authorization: Bearer API-KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "phone_number_id": "119153661148976",
    "phone_number": "5511999999999",
    "type": "document",
    "media_url": "https://exemplo.com/nota-fiscal.pdf",
    "filename": "nota-fiscal.pdf"
  }'
```
</CodeGroup>

## Resposta

```json
{
  "success": true,
  "data": {
    "message_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "message": "Message queued successfully."
  },
  "timestamp": "2026-09-08T19:30:00.000Z"
}
```

<Note>
  `message_id` é o identificador interno da WizeBot, e é ele que a [consulta de status](/tutoriais/api/status-mensagem-whatsapp) aceita. Guarde-o: sem ele não há como acompanhar a entrega.
</Note>

## Reenvio e duplicidade

<Warning>
  **Não há chave de idempotência.** Se a sua requisição sofrer timeout e você repetir, o destinatário pode receber a mensagem duas vezes. Antes de repetir, consulte o status do `message_id` que você já tem — ou registre o envio do seu lado antes de tentar de novo.
</Warning>

## Erros comuns

| HTTP | Código | Causa provável |
|---|---|---|
| 400 | `MISSING_PARAM` | Falta `phone_number`, ou `message` num envio de texto, ou `media_url` num envio de mídia |
| 400 | `INVALID_TYPE` | `type` fora da lista aceita |
| 400 | `INVALID_MEDIA_URL` | `media_url` não é endereço público válido |
| 404 | `CHANNEL_NOT_FOUND` | `phone_number_id` não pertence à sua empresa |
| 500 | `SEND_FAILED` | Número sem conversa anterior, texto acima de 4096 caracteres, conta desconectada ou teto de envio atingido |
